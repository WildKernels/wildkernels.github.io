Before anything

00 / the one paragraph everybody skips

Flashing a kernel can brick your device. Back up your data and keep an untouched boot.img you can fastboot back. Everything here is provided as-is — Wild Kernels is not responsible for damage, data loss or voided warranties.

Two things decide whether a build boots: the kernel version your phone currently runs, and the root flavour your manager speaks. Get either wrong and the phone bootloops or the manager reports a version mismatch. Both are covered below.

Installation

01 / Two paths: you already have root, or you patch boot.img yourself.

Caution. Wild Kernels is not responsible for bricked devices or damage. By flashing, you assume all risk. Back up your data and understand the risks before flashing.

Choose your method

Method When to use Requires root Guide
Kernel Flasher Upgrading with root already available, no PC needed Yes kernelflasher.md
magiskboot When you want to flash a pre-patched boot.img directly (no pre-rooted setup required) No magiskboot.md

Prerequisites

  • GKI 2.0 device with an unlocked bootloader
  • Full backup (at minimal the boot partition or have a stock unmodified boot.img)
  • Correct AnyKernel3 ZIP for your kernel version from Releases

Important. Match by the full kernel version (e.g., 6.1.x-androidXX) — your device's Android version and the androidXX in the kernel version are not necessarily the same. For example, as of writing, a Google Pixel 8 is on 6.1.157-android14 while the system Android is 17.

Kernel Flasher

02 / Upgrade from the phone. No PC, no fastboot.

Note. This method is more convenient when upgrading KernelSU and can be done without a computer.

See Installation for prerequisites, supported versions, and risks.

Prerequisites

  • Root access already granted to the flashing app (for first install from stock without root, use recovery/fastboot — see magiskboot)
  • AnyKernel3 ZIP matching your kernel version from Releases

Steps

  1. Download the AnyKernel3 ZIP from the latest Releases page.
  2. Open the Kernel Flasher app, grant root permissions when prompted.
  3. Select the AnyKernel3 ZIP and flash. Do not interrupt.
  4. Reboot when prompted and verify the manager shows the expected version.

magiskboot

03 / Repack a stock boot.img with a pre-patched kernel.

Use the official magiskboot build — works on Android and Linux.

See Installation for prerequisites, supported versions, and risks.

Platforms: Android · Linux

Preparation

  1. Get your device's stock boot.img.
  2. Download the AnyKernel3 ZIP for your kernel version from Releases.
  3. Unpack the ZIP and get the Image file (the KernelSU kernel).
Android — via adb + libmagiskboot.so

Folder structure on device (/data/local/tmp/):

/data/local/tmp/
├── magiskboot
├── boot.img
└── Image
  1. Download latest Magisk from GitHub Releases.
  2. Rename Magisk-*(version).apk to Magisk-*.zip and unzip.
  3. Push libmagiskboot.so to device: sh adb push Magisk-*/lib/arm64-v8a/libmagiskboot.so /data/local/tmp/magiskboot
  4. Push boot.img and Image: sh adb push boot.img /data/local/tmp/ adb push Image /data/local/tmp/
  5. Make executable: sh adb shell cd /data/local/tmp/ chmod +x magiskboot
  6. Unpack: sh ./magiskboot unpack boot.img
  7. Replace kernel: sh mv -f Image kernel
  8. Repack: sh ./magiskboot repack boot.img
  9. Test: fastboot boot new-boot.img
  10. Flash: fastboot flash boot new-boot.img
Linux — official magiskboot

Folder structure on PC:

.
├── magiskboot
├── boot.img
└── Image
  1. Prepare boot.img and Image on PC.
  2. Make executable: chmod +x magiskboot
  3. Unpack: ./magiskboot unpack boot.img
  4. Replace: mv -f Image kernel
  5. Repack: ./magiskboot repack boot.img
  6. Test: fastboot boot new-boot.img
  7. Flash: fastboot flash boot new-boot.img

Post-install

04 / Matching manager, SUSFS module, metamodules, verification.

After flashing a Wild Kernels GKI kernel, do these checks in order.

1. Download matching manager — KernelSU / KernelSU-Next / ReSukiSU

  • Download the manager-apk-* from the same Releases page you got the kernel from.
  • Install / update it over any existing manager.
  • Open the manager — it should show the kernel version you just flashed (e.g. 6.1.x-androidXX-Wild) and report "Working".

2. SUSFS

  • In the manager, install the sidex15/susfs4ksu-module.
  • Reboot.

3. Meta Module (if mounting modules)

If you need to mount modules, install one:

  • NoMount (Recommended) — NoMount-metamodule-*commit*.zip from Releases
  • Mountify — latest compatible module

Note. Only one is required. Compatibility with SUSFS shifts with updates.

4. DroidSpaces

  • Download the app: ravindu644/Droidspaces-OSS

5. Troubleshooting

Common issues
  • General issues — try restarting your device.
  • Bootloop — restore a stock boot.img via fastboot/recovery.
  • Manager and kernel version do not match (e.g. 31000 != 32000) — install the latest kernel and manager from the release and reboot.
  • Root not working — ensure the manager matches the flashed flavor (KernelSU / KernelSU-Next / ReSukiSU).
Nuclear option

Uninstall all modules and reboot, then delete all files and folders in /data/adb. Reboot again.

Caution. This wipes all KernelSU/Magisk module data — only use if nothing else works.

Configure a build

06 / Every Build Kernels input and what it changes.

Manual builds run from the Build Kernels workflow (Actions → Build Kernels → Run workflow). All options below are the dispatch inputs with their defaults.

Scope

  • Release Type (Action / Pre-Release / Release, default Action) Action builds and uploads artifacts to the run only — nothing is published. Pre-Release / Release publish a GitHub release under the next rN tag (Pre-Release is flagged as a prerelease).
  • Kernel Version (default All) — limits the build to one kernel line (e.g. 6.1.x-android14). All builds every line.
  • Patch date (YYYY-MM), kernel sublevel, lts, or All (default All) — narrows within the selected kernel line, e.g. 2025-07 builds just that month, 141 just that sublevel, lts just the LTS tip.
  • Render release notes preview only (default off) — renders the notes and stops. Skips all builds and any release. Use it to check notes before a real run.
  • Kernel Branding (default Wild) — name stamped into the build.

Sources

  • Commit mode (latest / verified / update, default verified)
  • latest resolves every component to its branch tip at run time.
  • verified uses the audited pins in main.yml for NoMount, the KernelSU / ReSukiSU / SukiSU-Ultra roots, and SUSFS (KernelSU-Next, KowSU, kernel_patches, AnyKernel3, and DroidSpaces always track latest).
  • update builds at latest, then promotes the verified pins to what just built successfully.

Root

  • Root Flavor (default All) — All builds KernelSU-Next, KernelSU, and ReSukiSU. SukiSU-Ultra, KowSU, and No Root are opt-in only. KowSU cannot be combined with SUSFS — run it with SUSFS off.
  • SUSFS (default on) — kernel-level root hiding.
  • NoMount (default on) — VFS hooks.
  • DroidSpaces (default on) — chroot/distro support.

Protections & subsystems

  • Baseband Guard (default on) — baseband protections.
  • Networking (default on) — networking stack additions.
  • NTSync (default on) — NT synchronization primitives.
  • Ptrace Patch (default on) — ptrace hardening adjustments.
  • Unicode Fix (default on) — version-specific unicode fixes.
  • BPF Stack (default on) — BTF + eBPF + FUSE-BPF.
  • Performance (default off) — extra performance patches. Off by default; enable only if you want them.

Build behavior

  • Use ccache/bazel cache (restore/save) (default on) — reuses compiler caches across runs. Turn off for a fully clean build.
  • Force-load modules with mismatched symbol versions (default off) — patches the module loader's bad_version path to accept instead of reject, so version-mismatched modules load. Only needed for kernels that would otherwise refuse the build.
